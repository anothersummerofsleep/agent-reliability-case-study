# Agent Reliability Case Study

An **evaluation-first** LangGraph agent for equipment-operations incident support, built as an
engineering case study in agent *reliability*: the interesting part is not the agent, it is the
deterministic policy, the evaluation harness, and the trace-driven improvement loop around it.

> **Status: Phase 1 (real components + first baseline).** The four behavioral stubs are replaced with
> the smallest real implementations: a bounded Evidence Investigator, a BM25 retriever over the
> fictional Northwind corpus, a structured Diagnosis Specialist, and a bounded Grounding Validator. The
> goal of this phase is an honest **first baseline** against the frozen evaluation cases, not a tuned
> system: it answers "can the real agent execute the frozen workflow, and where does it fail?" Failures
> are recorded, not tuned away. The trace-driven improvement loop is a later phase.

## What this is, honestly

- **Portfolio-scale**, **evaluation-first**, **production-oriented**. It is a case study, not a
  production system.
- The domain is a **fictional** commercial-HVAC equipment family ("Northwind"). Every incident,
  alarm code, and manual is invented. There is **no** real production traffic, **no** real enterprise
  users, and **no** proprietary or employer data of any kind.
- It does **not** represent 2+ years of production-agent tenure. It is one carefully-engineered,
  deeply-evaluated system.

## Design in one paragraph

An incident enters, is routed (`INVESTIGATE` or `OUT_OF_SCOPE`), and flows through an Evidence
Investigator, a Diagnosis Specialist, and a bounded Grounding Validator. A single **deterministic
policy** (one pure function, evaluated at three checkpoints) decides the final outcome:
`ANSWER | ASK | ESCALATE | ABSTAIN`. The model never decides whether to abstain; a policy does. State
is **progressive** (later-stage fields are absent until their node runs), and the policy uses explicit
guarded comparisons so a missing value never silently satisfies a later rule.

## Quickstart

```bash
uv sync --extra dev        # create the venv and install deps
uv run pytest              # run the deterministic suite (no API keys needed)
```

The test suite runs fully offline using fake models (every model-backed step is injectable). To
exercise a **real** model call and see a LangSmith trace:

```bash
cp .env.example .env       # then fill in GOOGLE_API_KEY and LANGSMITH_API_KEY
uv run python -m agent_reliability.graph "RTU-40 unit 3 tripped NW-A11, discharge 415 psi, coil fouled"
```

Secrets come from environment variables only; `.env` is gitignored.

## Baseline evaluation

Phase 1 produces the first per-dimension baseline over the **E2E** cases (fault-injection UNIT cases
ARC-19/20 stay deterministic tests, excluded from model metrics). It needs live credentials:

```bash
cp .env.example .env       # GOOGLE_API_KEY, LANGSMITH_API_KEY, LANGSMITH_TRACING=true
uv run python -m agent_reliability.evaluate baselines/baseline-v1.json
```

This runs the real graph over each case, scores route / decision / reason / retrieval-behavior /
retrieval-source / distractor-resistance / grounding / structured-output validity / latency
**separately** (there is deliberately no composite "agent score"), and writes a reproducible artifact
recording the commit, model, dataset identity, and per-case results. See `baselines/README.md`. Do not
tune prompts, retrieval `k`, or thresholds before the baseline is captured: a poor baseline is useful
evidence.

## Layout

```
src/agent_reliability/   contracts, enums, deterministic policy, safety detector, graph, nodes,
                         retrieval (BM25), model, dataset, evaluate (baseline harness)
datasets/                the 22 frozen seed evaluation cases + fictional Northwind corpus
baselines/               reproducible baseline artifacts (generated by the evaluate harness)
tests/                   deterministic contract / policy / safety / dataset / retrieval / investigator /
                         diagnosis / grounding / evaluate / graph tests (all offline)
docs/decisions/          architecture decision records
```
